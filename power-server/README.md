# Сервер управления питанием с iPhone

**Русский** | [English](README.en.md)

Восстановлен из исходного скрипта пользователя: HTTP на порту **5154**, версия API **1.1.0**, команды сна, выключения и перезагрузки. Исправлено форматирование, добавлена проверка некорректного JSON/таймера и ограничение тела запроса. Файл службы подготовлен для этого репозитория; исходный unit с устройства не получен.

Сервер запускается на управляемом Linux-компьютере с Python 3 и systemd. Дополнительных Python-пакетов нет. Он не будит компьютер: для этого iPhone отправляет Wake-on-LAN. Сервер принимает команды только пока компьютер включён.

**В исходном протоколе нет пароля и шифрования. Любое устройство, имеющее доступ к TCP 5154, может усыпить, выключить или перезагрузить компьютер. Используйте только доверенную локальную сеть, не пробрасывайте порт в интернет.**

## Установка на SteamOS / Linux

Скопируйте каталог `power-server` на управляемый компьютер. В Desktop Mode откройте терминал в этом каталоге. Команды выполняются от обычного пользователя, не root:

```sh
mkdir -p ~/Applications/MagicPacket/custom ~/.config/systemd/user
cp server.py ~/Applications/MagicPacket/custom/server.py
cp magicpacket.service ~/.config/systemd/user/magicpacket.service
systemctl --user daemon-reload
systemctl --user enable --now magicpacket.service
systemctl --user restart magicpacket.service
systemctl --user status magicpacket.service
```

Если сервер уже установлен, сначала сохраните копии существующих `server.py` и unit-файла: эти команды заменяют их. Порт 5154 должен быть свободен. При наличии файрвола разрешите входящий TCP 5154 только из доверенной сети.

Служба запускается с пользовательской сессией. Если нужна работа до входа пользователя, можно включить `sudo loginctl enable-linger "$USER"`; это также сохраняет работу остальных пользовательских служб после выхода.

Разрешение на `systemctl suspend`, `poweroff` и `reboot` зависит от systemd-logind/Polkit вашей системы. Сервер не обходит эти права. Если запрос принят, но действие не выполняется, проверьте журнал службы и разрешения пользователя. Сам факт запуска службы не доказывает наличие этих прав.

## Настройка на iPhone

Телефон и компьютер должны быть в одной доступной локальной сети. Желательно закрепить IP компьютера в DHCP-настройках роутера. В клиенте Magic Packet, поддерживающем этот HTTP API, укажите IP компьютера и порт сервера **5154**. Названия полей зависят от клиента. MAC-адрес для пробуждения возьмите из AV Switcher; HTTP-порт сервера не является UDP-портом Wake-on-LAN.

Можно использовать приложение iOS «Команды» напрямую:

1. Создайте команду, добавьте URL `http://IP_КОМПЬЮТЕРА:5154/control/sleep`.
2. Добавьте «Получить содержимое URL», выберите метод **POST**, тело запроса **JSON**.
3. Добавьте числовое поле `timeout` со значением `0` для выполнения примерно через секунду или, например, `30` для задержки.
4. Для выключения используйте `/control/shutdown`, для перезагрузки — `/control/reboot`. При желании добавьте подтверждение перед запросом и ярлык на экран «Домой».

Перед проверкой сохраните документы и игры. Ответ `{"status": true}` означает принятие запроса, а не успешное завершение действия. Отложенная команда хранится в памяти и пропадёт при остановке сервера; каждый повторный POST планирует новое действие.

## API

| Метод | Путь | Ответ / действие |
| --- | --- | --- |
| GET | `/info/version` | `{"version": "1.1.0"}` |
| GET | `/info/status` | `{"status": true}` |
| POST | `/control/sleep` | `systemctl suspend` |
| POST | `/control/shutdown` | `systemctl poweroff` |
| POST | `/control/reboot` | `systemctl reboot` |

POST принимает JSON-объект `{"timeout": 0}` либо пустое тело. Задержка ограничена диапазоном 0–300 секунд, фактический минимум — 1 секунда. Некорректное тело возвращает HTTP 400, неизвестный путь — 404.

Безопасная проверка без изменения питания:

```sh
curl http://127.0.0.1:5154/info/version
curl http://127.0.0.1:5154/info/status
```

Для проверки с другого устройства замените `127.0.0.1` на IP компьютера.

## Обслуживание

```sh
journalctl --user -u magicpacket.service -n 50
systemctl --user restart magicpacket.service
systemctl --user disable --now magicpacket.service
```

Последняя команда отключает сервер и автозапуск. После этого можно удалить установленные файлы. AV Switcher продолжает работать без сервера, показывая его как неактивный.
